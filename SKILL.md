description: Start, stop, configure, or inspect a local animated agent monitor for Claude Code and Codex chats on Linux, including Claude Code in VS Code terminals and Codex in the ChatGPT desktop app or VS Code extension. Use for per-chat activity avatars, not selecting the native ChatGPT Pet.

# Agent Monitor

Use the bundled `scripts/monitor.py` with Python 3. It runs a local Tk desktop window and reads Claude Code lifecycle hooks; routine animation and status updates need no model calls. Assets are bundled. Do not regenerate artwork or poll chats with an agent.

Resolve this skill's installed directory, then run:

```sh
python3 <skill-dir>/scripts/monitor.py status
python3 <skill-dir>/scripts/monitor.py start
python3 <skill-dir>/scripts/monitor.py stop
```

For first setup or hook repair, run `install-hooks`, then `start`. The installer backs up and merges `~/.claude/settings.json`, preserving unrelated hooks/settings. For Codex chats, also run `install-codex-hooks`: it backs up and merges `$CODEX_HOME/hooks.json` (default `~/.codex/hooks.json`) with this monitor's `hook codex` command for every Codex hook event; Codex then skips the hooks until the user approves them once via `/hooks` or the app's "Hooks need review" prompt, so never claim Codex cards work before that. `uninstall-codex-hooks` removes only those entries. Codex hooks need a Codex build with the `hooks` feature (the desktop app and VS Code extension builds have it; the older `/snap` CLI 0.114 does not). `uninstall-hooks` removes only this monitor's exact hook commands. Use normal filesystem/desktop permission mechanisms when necessary.

One card represents one open interactive Claude Code session; idle/completed sessions remain until closed. Cards are added/removed automatically and labeled with the chat title (the `/rename` name, else Claude Code's `ai-title` from the transcript), the project (the folder the session was launched in, unaffected by renames or later `cd`s), and a short session ID; before a title exists the card shows project and session ID only. Tifa, Rinoa, and Yuna are registered. Additional saved avatars can be registered with `add-avatar NAME DIRECTORY`; either provide the base five GIFs (`idle`, `running`, `waving`, `waiting`, `failed`) or an `animations.json` mapping every state to existing themed GIFs. Registration validates every resolved scene; then click the name button under a card's avatar to open a picker popup (an RPG-style list with each avatar's idle thumbnail) and choose that chat's avatar; the picker re-reads the catalog each time it opens, so newly added avatars appear without restarting. New chats rotate through the available catalog. These are local monitor avatars; registration does not upload them as native ChatGPT Pets.

`status` reports monitor health, active sessions, and each session's details. The window, header, usage gauges, and every card are framed in the bordered style of classic RPG dialogue windows, and each state label carries its own small hand-drawn pixel icon in that same idiom (sword = acting, skull = KO'd/errored, sleeping moon = idle, question mark = needs a choice, …) — original shapes procedurally drawn in `draw_icon()`, not art copied from any specific game. Hooks map to these states, icons, and sprite animations:

The following are default mappings. An avatar's optional `animations.json` overrides them with ordered GIF basename choices. The first existing file wins; missing scenes fall back to idle. All three use neutral default idle poses, also used by the picker thumbnails. Tifa plays piano during background waiting, studies materia while reading, and fights Bomb/Cactuar during execution. Rinoa pets Angelo during background waiting, reads a briefing while thinking, and fights Bomb/Bite Bug during execution. Yuna plays with a Moogle during background waiting, prays while thinking, and uses Valefor/Water Flan scenes during execution; delegation uses Valefor. Rinoa/Yuna have separate waiting and hurt poses. For Tifa, thinking/compacting use chin-rest thinking (historically named `running.gif`); delegation/needs-input use guard; ready uses her neutral standing pose; failures use hurt. This removes generic running, full-turn scanning, jumping, and repeated waving. Tifa victory scene remains pending. Optional `variants.json` lists `working` and `background` scene basenames. Working encounters rotate every 8–14 seconds; quiet background variants every 25–45 seconds, without immediate repeats. Idle/picker, approval and error poses stay fixed. Local background variants include Tifa at Seventh Heaven, Rinoa fetching with Angelo and Yuna embracing Valefor. Lightning may name a `busy_shift` GIF: it plays once on a change between busy roles, at most every 30 seconds, and yields immediately to alerts or an avatar change. All sprites and picker thumbnails use a common 4:3 transparent canvas, preserving source proportions without stretching. Adding variants to an already-loaded avatar needs a monitor restart.

The local working rotation also includes `dolphin-sweeper` (Tifa's Dolphin Blow versus a Sweeper), `angel-wing-trexaur` (Rinoa's Angel Wing and Meteor versus a T-Rexaur), `shiva-bomb` (Yuna and Shiva's Diamond Dust versus a Bomb), and `army-of-one-behemoth` (Lightning's Army of One versus a Behemoth King). These are six-frame transparent loops alongside the existing encounters. Source sheets and exact built-in image generation prompts stay local in `artwork/<character>/`; GIFs stay in `assets/<character>/`, all excluded from Git.

Codex tool mapping recognizes dotted and MCP namespaces, user questions, agent lifecycle tools, planning calls and tool-output waits. `exec` wrappers are classified from explicit nested tool calls and simple read-only shell commands; mixed/ambiguous commands remain Working. Tool input is inspected transiently and never retained; only resolved tool names and counts are saved. Cards show the action without a long MCP prefix. Optional `thinking`/`reading` variants rotate every 12–20 seconds and `delegating` variants every 10–16 seconds. Tifa alternates thought and materia study; Yuna alternates Valefor and Shiva delegation scenes. Idle, Needs input and Error remain fixed.

| State | Trigger | Default animation |
|---|---|---|
| Idle | session start, interrupt | `idle` |
| Thinking | prompt submitted, between tools, after compaction | `review` |
| Reading | Read/Grep/Glob/LS/WebFetch/WebSearch and similar read-only tools | `review` |
| Working | edits, image generation, other or ambiguous commands (card shows the tool name) | `running` |
| Delegating | Agent/Task/spawn/send/wait-agent tools, subagent activity (shows active subagent count) | `running-right` |
| Compacting | `PreCompact` until `PostCompact` | `idle-jump-idle` |
| Needs input | permission prompt, elicitation, AskUserQuestion, ExitPlanMode | `waiting` |
| Background ×N | stopped/idle while background Bash, Monitor, or subagents still run | `look-loop` |
| Ready | `Stop` with nothing left running (brief `jumping` flash, waves for 60 s, then idles) | `waving` |
| Error | `StopFailure` (API/turn failure) | `failed` |

Background jobs are tool calls with `run_in_background: true` (only that flag is read) plus every `Monitor` call, keyed by `tool_use_id`; each clears when the transcript's `<task-notification>` for that ID reports a final status, or after 12 hours. Background subagents clear on `SubagentStop`. Work Claude does after a notification wakes it counts toward turn and active time.

Every card uses the same label layout — chat name, then the project folder (when known) and short session ID — and a small `CLAUDE`/`CODEX` tag in its corner says which agent it is. Loaded Codex threads are also detected without hooks: a running Codex app server (process name starting `codex`) holds each loaded thread's rollout open, so those rollouts get cards marked `detected`, with state from the last `task_started`/`task_complete`/`turn_aborted` record (thinking/ready/idle); the hooks add live tool, permission and subagent states once approved. A detected card leaves when its thread is unloaded or the process exits. A Codex `SessionEnd` keeps a thread hidden only while the process that held it then still holds it: Codex sends no SessionStart when an app restart merely reloads a thread, so a thread reopened by a newer process is detected again. Codex chats share one long-lived app process, so a hooked Codex card leaves on Codex's `SessionEnd`, when that process exits, or after 2 hours idle/ready/errored while its thread is no longer loaded (a card waiting on approval stays). Codex's internal approval-review and subagent threads (`thread_source` `guardian_review`/`subagent` in the rollout's first `session_meta` line) never get cards, and neither does any Codex hook event without a `.jsonl` `transcript_path`: ephemeral sessions such as an approval's Guardian review report none (and a different session ID from their thread) and may never send Stop, while real chats always have a rollout. A busy hooked Codex card whose rollout is not held open (e.g. VS Code extension chats) is still corrected from its rollout when a `task_complete`/`turn_aborted` newer than its last event shows a missed Stop. A Codex card's details come from its rollout file (`token_usage_record` counts deduped by response ID, `turn_context` model, `model_context_window`, `compacted` markers) and its chat name from Codex's state database (`state_5.sqlite` `threads`, opened read-only: the sidebar `name`, else the first-message `title` with markdown links reduced to their label, re-read at most every 5 s), else `session_index.jsonl`; message text is never kept. Stop, SubagentStop and Interrupt Codex hooks print `{}` because Codex rejects non-JSON output for them; all other hooks stay silent.

The header has one usage box per provider with two bars, each marked by a pixel icon from `draw_ui_icon()`: a pocket watch for the short (5h) window and a calendar for the weekly (7d) one. The OpenAI box polls `account/rateLimits/read` every 5 minutes (every minute once a window's reset time has passed, until a fresh reading arrives) by starting Codex's own app server (`codex app-server`, JSON-RPC over stdio; `"codex_binary"` in config.json overrides the executable, else the desktop app's, VS Code's, then PATH) and closing its input so it exits. Codex makes that request with its own login and refreshes it itself; the monitor never reads `auth.json` or any OpenAI token. Failures back off exponentially (up to an hour) and keep the last reading, saved in `codex_limits.json` in the state directory. A newer `rate_limits` reading Codex logs with a response (`limit_id` `codex` in the newest rollouts under `$CODEX_HOME/sessions`) wins over the poll. The OpenAI line also shows `limit reached` and the number of free rate-limit resets available; reset times always come from the newest reading's `resetsAt`. Google/Gemini is not included. The Anthropic box shows the signed-in Claude account (organization, plan, rate tier, email, from `~/.claude.json`) and two account-wide gauges of what is left in the **5h** and **7d** usage windows, with time to reset. Set `"expected_org": "<organization name>"` in config.json to flag the header when Claude Code is signed in to a different organization (for example a personal Pro org instead of Team).

Readings come from Anthropic's usage endpoint (`/api/oauth/usage`, the one `/usage` uses) with Claude Code's current access token from `~/.claude/.credentials.json`. The token is sent only to api.anthropic.com, never logged or stored, and never refreshed by the monitor; an expired token simply skips the call until Claude Code renews it. Calls cost no model tokens. The window polls at most every 5 minutes, and only while a session is active, after a window resets, or after an account switch; HTTP errors back off exponentially (honouring `Retry-After`, up to an hour). When the API is unavailable, Claude Code's own cached `/usage` reading for the same account is used. Between readings, a `~` marks values extrapolated from this machine's transcript tokens (cost-weighted) at a rate calibrated from consecutive readings in the same window; usage on other devices only appears at the next reading. `limits.json` in the state directory holds readings and calibration, not the token.

A failed tool call only flashes `failed` briefly and increments the error count; Claude usually recovers, so it no longer pins the card on Error. Stopping a response means ready, not proven task success.

Sound: a character plays music only from files the user supplies. Never download, bundle, or generate copies of copyrighted game music; a character without files stays silent. An optional `music.json` in the character's folder lists playlists by file name: `field` (calm music), `battle`, `boss`, and `victory`, each a name or list (`.ogg`/`.opus`/`.mp3`/`.flac`/`.m4a`/`.wav`; missing files are skipped), plus an optional `victory_seconds`. Without a `field` list, `set-theme NAME FILE` (stored in config.json; `set-theme NAME` clears it), else `theme.<ext>` in the folder, is the field music. Music starts per turn, not per state, because Claude flips between thinking and tools every few seconds: a busy chat (thinking/reading/working/delegating/compacting) gets music once its turn has run `"music_delay"` seconds (default 5, so short tasks stay silent). The mood comes from the pace of the chat's provider usage (Claude chats the Anthropic gauges, Codex chats the OpenAI ones): for each window, the projected percent used by its reset if the current burn continues, which the bars show as `pace N%`. The 5-hour window uses the last 30 minutes of burn (Anthropic: this machine's transcript tokens at the calibrated rate; Codex: how fast its logged readings climbed), falling back to the average since the window began; the weekly window always uses that average, counted over at least a seventh of the window so a busy first hour is not stretched across a week of nights. The worse window decides: field while the projection is under `"pace_calm"` (80), battle up to `"pace_limit"` (100), and boss beyond that, with under `"boss_left"` (10)% left, or once a limit is reached (OpenAI's limit-reached flag; a reached limit normally fails the turn, so the music stops anyway). A mood changes only once the projection is 5 points past a threshold, so estimated values cannot make it flicker; without a reading the last mood stays (field at first). The mood does not lock a playlist, it weights the draw (`MOOD_MIX`: field mood 70/22/8 field/battle/boss, battle mood 25/50/25, boss mood 8/27/65): each time a track is needed a kind is drawn by those weights among the kinds that have tracks, and that track plays to its end before the next draw, so a mood change takes effect at the next track. `status` shows each provider's current mood. Each playlist is shuffled (every track once per round, never twice in a row) and remembers its position: a track that stops resumes where it left off (with a 1.5 s fade-in) and the next track starts when it ends, so many short turns walk through long tracks instead of replaying their intros. A Ready after a turn of at least `"victory_after"` seconds (default 30) plays the character's victory track, cut to `victory_seconds` (default 7, global `"victory_seconds"` in config.json) with a fade-out, instead of the Ready chime, and holds other music until it ends. A chat in the `background` state (turn over, background jobs or subagents still pending) also plays music, at `"background_volume"` (0–100, default half of `theme_volume`); busy chats always take priority over it, and with only background chats the music rotates to the next one at the first track end after 120 s (`BACKGROUND_ROTATE`), so a track is never cut for rotation; idle, ready, error and waiting chats never play. Playback is through `ffplay` (`"theme_volume"` 0–100 in config.json, default 60), one chat at a time: the chat already playing keeps it, otherwise the most recently started busy, unmuted chat takes over; music survives a pause of up to 3 s, and a file ffplay cannot play is skipped until the monitor restarts. `status` lists each character's resolved playlists and the timing settings. Players die with the monitor (`PR_SET_PDEATHSIG`). Original jingles in a 16-bit RPG style (`CHIMES`: pulse-wave melody over a triangle bass, harp-like ringing notes, slight vibrato, SNES-style echo; generated into the state directory; composed for this monitor, not tunes or sound effects from any game: Needs input is a rising Dmaj9 arpeggio left hanging on its ninth plus a menu-cursor ping, Error a game-over-style A minor descent through the leading tone, Ready a G major flourish) play through `pw-play`/`aplay` when a chat becomes Needs input or Error (the `"chimes"` list in config.json; default `["waiting", "failed"]`, add `"ready"` for a chime after every turn, `[]` for none), at most one per 1.5 s overall and once a minute per chat and kind, never for a card's first appearance; a long turn's Ready plays its victory fanfare instead. Each card's speaker button mutes that chat's music and chimes (`muted` in the sessions table, kept across hook events); the header speaker is the master mute (`"sound"` in config.json).

The header has three pixel-icon buttons. The `?` opens an in-window help panel (drawn as a classic RPG dialogue box, not an OS dialog) that explains the states, the clock/calendar usage bars, card details, and privacy; `?` again, `▶ OK`, Esc, or Enter closes it. The speaker is the master mute. The lines button toggles per-card details (saved as `verbose` in config.json): session age, active time, current/last turn duration, prompt/tool/error/subagent counts, context used versus window with a bar, total input (with cache-hit %) and output tokens, model, API calls, compactions, permission mode, and time since the last event. Token figures come from the numeric `usage` fields of the session's transcript (including subagent transcripts), read incrementally by the window; dedupe is by message ID. The context window is 1M for `[1m]`/Opus 5 models or once usage exceeds 200k, otherwise 200k; set `"context_window": N` in config.json to override.

Existing sessions are discovered through local Claude session metadata when available (an implementation detail, not a guaranteed API); their status is approximate until hooks arrive. PID/start-time checks remove crashed sessions. Hook payload prompts, tool arguments and outputs are not stored; only event counts, tool names, background `tool_use_id`s, timing, permission mode, and the transcript path are. Transcript message text is never kept or displayed; only token counts, model ID, compaction markers, finished background job IDs, and the chat title records are extracted.

A card is added or removed purely by what Claude Code reports: it appears when a session starts and disappears once its process ends (via a real `SessionEnd` hook or the next liveness check finding the process gone). There is no manual way to pause, archive, or delete a card from the monitor — nothing in this tool can reach into a session to end it, so a control that only hid a card without doing that would be misleading busywork, not a real action.

Session health: small pixel marks after a card's status, in compact mode too, only when they apply; hovering one shows its numbers and advice, and the help panel's SESSION HEALTH legend explains them (the card itself carries no advice text). A scroll appears yellow (long) once the context reaches `"context_warn"` (40)% of its window, `"tokens_warn"` (150000) tokens, or one compaction, and red (too long) from `"context_bad"` (70)%, `"tokens_bad"` (300000) tokens, or two compactions; the token limits apply on 1M windows too, where a third full is already a very large context. A burst marks a running turn with `"struggle_errors"` (3) or more tool errors, or one longer than `"long_turn"` (1200) s with `"long_turn_tools"` (40) or more tool calls (per-turn counts reset when the turn ends). A snowflake marks a non-busy chat with at least `"cold_tokens"` (50000) context tokens idle for `"cache_ttl"` (300) s, the prompt-cache lifetime, after which its next turn re-reads the whole context at full price. No sound is tied to any of these. `status` includes each session's health and flags as text.

Remote machines over SSH: `remote-add TARGET [NAME]` (TARGET is an SSH target or `~/.ssh/config` alias; NAME defaults to it) checks for Python 3.9+ there, copies this script to `~/.agent-monitor/monitor.py` on the host, and runs its `remote-setup`, which marks that host headless (its hooks record events but never open a window) and installs its Claude Code hooks (and Codex hooks if `~/.codex` exists; approve those once in Codex there). Rerun `remote-add` to update the remote copy after changing this script. SSH must already work without a password (key, `ssh-agent`, or `~/.ssh/config`): every call uses `BatchMode=yes`, and `StrictHostKeyChecking=accept-new` accepts a new host key once and refuses a changed one. The window keeps one long-lived connection per host running `monitor.py snapshot watch` there, which prints the host's sessions (with transcript usage, read and reconciled on the host) as a JSON line whenever they change and at least every 30 s; one persistent process keeps the transcript readers warm instead of re-reading every file per poll. Remote chats become ordinary cards tagged `CLAUDE · NAME`/`CODEX · NAME`, with times shifted onto the local clock; they take part in music, chimes and victory fanfares, and their avatar and mute choices are kept locally in `remote_prefs.json`. A dropped connection retries with backoff (5 s doubling to 60 s), keeping the host's last cards greyed and marked `offline` until it answers. `status` lists each remote's connection state, last error, and session count while the window runs (the window keeps them in `remotes.json`); the connection's stderr is in `remote-NAME.log` in the state directory. `remote-remove NAME` uninstalls that host's hooks (best effort) and unregisters it, leaving its files in place. The usage bars stay local: Anthropic limits are account-wide, so a remote on the same account is already counted.

The window can be dragged by its title strip, resized, minimized, or stopped with its close button. `stop` also disables automatic launching until `start`. Hooks start the enabled monitor on later activity. Existing Claude sessions may need `/hooks` review/restart to pick up newly installed hooks; never interrupt them automatically.

If display access or Tk/Pillow is unavailable, report the actual error. Do not claim visibility from installation alone. This monitor does not drive native ChatGPT Pets, control Claude, or send messages. For implementation details and regression verification, use the bundled scripts and `python3 -m unittest discover -s <skill-dir>/tests`.

Card backdrops follow the existing per-provider music mood even with sound muted: field teal, battle warm slate, boss plum. Borders and icons retain task-state colors. Set `"mood_backdrops": false` in config.json for the original card background.
